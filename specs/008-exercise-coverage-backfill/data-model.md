# Phase 1: Data Model — Exercise Library Coverage Backfill

**Date**: 2026-09-21
**Status**: Complete

## Overview

No schema change. This feature adds rows to the existing `Exercise` entity
(specs/007-exercise-library-migration/data-model.md) and introduces one new **file-based** data
shape (not a database table) that feeds those new rows.

---

## Entity: Exercise *(existing — specs/007, unchanged structure)*

No new columns, no new constraints. This feature adds ~54 new rows, each satisfying the exact same
validation rules already enforced by `upsertExercise()`:
- `name`: non-empty, ≤255 chars, unique case-insensitively.
- `video_url`: when present, `http(s)` — and per spec FR-004, every new row's `video_url` MUST be
  present and MUST point to a real, verified video (not left `NULL`, unlike specs/007's Exercise
  entity, which allows `NULL` for a not-yet-linked exercise in general).
- `category`: free text, assigned per spec FR-005 from the same five groupings specs/007 already
  established (Strength — Upper Body, Strength — Lower Body, Core, Cardio, Flexibility & Mobility) —
  or a sensible new grouping if a missing exercise genuinely doesn't fit one (documented per-entry
  in the backfill data file's own comments if that happens).

---

## New shape: Missing-Exercise Backfill Entry *(file data, not a table)*

**Purpose**: The curated, researched source data `backfill-missing-exercises.js` reads and upserts
— the equivalent role `exercise.md`'s rows played for specs/007's original migration, for this
round's 54 additions.

**Location**: `app/server/scripts/missing-exercises-data.js`, a plain ES module exporting an array.

**Structure**:

```js
export const MISSING_EXERCISES = [
  { name: 'Barbell Bench Press', category: 'Strength — Upper Body', videoUrl: 'https://...' },
  // ...
];
```

| Field | Type | Constraints |
|---|---|---|
| `name` | string | Exactly as it appears in the customer program(s) that reference it (spec FR-001/FR-002) — no rewording, no translation, no splitting a compound line (spec FR-008). |
| `category` | string | One of the five existing groupings, chosen by what the exercise actually is (spec FR-005). |
| `videoUrl` | string | A real, currently-accessible `http(s)` URL, individually verified during research (spec FR-004) — never a generic search-results link or a guessed video ID. |

**Relationship to Exercise**: Each entry becomes exactly one `upsertExercise(name, { category,
videoUrl })` call (specs/007 contracts/exercise-data-api.md, unchanged) — the same function, same
validation, same case-insensitive-name-uniqueness guarantee already in place.

**Provenance note**: The 54 names this file must cover (as of this writing) are enumerated in
`contracts/coverage-check.md`'s Acceptance Criteria — generated by running
`check-exercise-coverage.js` against current data, not hand-curated from scratch.
